> **类型**：操作手册 ｜ **最后更新**：2026-11-10 ｜ **适用版本**：0.1.x

| | |
|---|---|
| **模型格式** | `format = "bbpe-rs-model"`，`format_version = 1` |
| **命令行入口** | `bbpe <子命令>`（`train` / `sweep` / `cut` / `sample` / `compare` / `inspect` / `encode` / `decode`） |

## 1. 30 秒上手

```bash
# ① 训练一个词表（语料 jsonl，每行 {"text": "..."}）
cargo run --release --bin bbpe -- train \
    --input data/train.jsonl --format jsonl \
    --vocab 100256 --output output/vocab_100k.json

# ② 检查模型（出身信息 + 自洽性校验）
cargo run --release --bin bbpe -- inspect output/vocab_100k.json

# ③ 命令行直接编码 / 解码（训练产物 → 使用的闭环）
cargo run --release --bin bbpe -- encode --model output/vocab_100k.json --text '你好，世界'
cargo run --release --bin bbpe -- decode --model output/vocab_100k.json --ids 104,101,108   # hel

# ④ Python 里用
python -c "
import bbpe_rs
tok = bbpe_rs.BBPETokenizer('output/vocab_100k.json')
ids = tok.encode_ordinary('人工智能是计算机科学的一个分支')
print(ids[:10], tok.decode(ids))
"
```

## 2. 一条命令覆盖两种语料规模

语料能否装进内存是**连续量**，不该让用户在两个产品之间做选择。所以：

| 你的语料 | 命令 | 语义 |
|---|---|---|
| 能装进内存 | `bbpe train --input corpus.jsonl --vocab 100256` | **全量精确训练**（不采样，严格等价） |
| 远超内存（几十 GB ~ TB） | 同上 **+ `--sample-rate 0.2 --heldout-rate 0.005 --heldout-out heldout.jsonl`** | 行级随机采样训练 + held-out 验收 |

**不传 `--sample-rate` 就是全量训练；传了就采样。** 其余参数、模型格式、下游用法完全相同。

内存预算（经验值）：峰值 RSS ≈ `9.2 × 训练语料字节数`。`bbpe train` 会在开工前做预检：
超预算时**不硬扛到 OOM**，而是直接给出可直接复制的降采样命令。

## 3. 安装与构建

```bash
# 一次构建，产出全部工具（零剖面；--no-default-features 不拉 pyo3）
cargo build --release --no-default-features

# Python 绑定（maturin；默认 feature 才带 pyo3）
pip install maturin
maturin develop --release          # 或 maturin build --release 出 wheel
```

> **依赖说明**：默认只依赖 `jinja2` —— 只想用分词器 / 训练器**不必安装 torch**。
> `torch` 与 `transformers` 已移入可选 extra `logits`，只有
> `UTF8StrictLogitsProcessor`（推理侧的 UTF-8 **前导字节级**约束，类名为历史名称）需要它们：
> ```bash
> pip install ".[logits]"          # 或 pip install bbpe_tokenizer[logits]
> ```

产物在 `target/release/`。入口是 `bbpe`，每个子命令也可单独调用（`train` / `sweep` / …，参数相同）。

| 类别 | bin |
|---|---|
| 统一入口 | `bbpe` |
| 子命令（等价的独立调用形式） | `train`、`sweep`、`cut`、`sample`、`compare`、`inspect`、`encode`、`decode` |
| 通用基准 / 进阶 | `bench`、`bbpe_jsonl_bench`、`run_real_data`、`freeze_probe` |
| 过渡别名（打印提示后转发） | `train_vocab`、`sweep_vocab`、`cut_vocab`、`sample_corpus`、`inspect_model`、`compare_merges` |

跑测试：

```bash
cargo test --release --no-default-features             # 常规
cargo test --release --no-default-features -- --ignored  # 追加统一构建检查（较慢）
```

## 4. 核心概念

### 4.1 词表与 id 规则

- 基础词表 = 256 个字节（0–255）
- 第 `i` 次合并产生的新 token 的 id = **`256 + i`**（合并次序被编码进 id）
- 因此 `new_id` 天然连续，且**按 id 排序 == 按合并次序排序**
- special token 的 id 分配在尾部：`base_vocab_size + i`，其中 `base_vocab_size = vocab_size − special 数`

> **全书统一的单位**：总词表 = 256 基础字节 + merges 数 K。
> `train --vocab`、`sweep --vocabs`、`cut --vocab` 三处**同口径**；K 只在输出里作为对照列出现。

### 4.2 贪心前缀性质（本项目的关键杠杆）

> **前 k 次合并 == 用总词表 256+k 直接训练所得的合并序列。**

已由实测确证（150K→100K 截断与直接训练 100K **100,000/100,000 逐位一致**），并有小规模常驻回归测试。

推论：

- 训一次 `K_max`，就能**零成本**评估/导出任意 `K ≤ K_max`（`sweep` / `cut` 就是这个原理）
- **选 K 不需要重训**

### 4.3 预分词 pattern

内置三种（`pre_tokenizer.rs`）：

| 常量 | 说明 |
|---|---|
| `PATTERN_CHINESE_OPTIMIZED`（**默认**） | 汉字连缀 + 英文缩写 + 数字 + 标点 + 空白，中文场景优化 |
| `PATTERN_GPT4` | cl100k 风格 |
| `PATTERN_LLAMA3` | Llama-3 风格 |

**pattern 是模型的一部分**，训练时写入 `pre_tokenizer_pattern` 字段；加载时缺失会**直接报错**（不再静默 fallback）。自定义 pattern 见 §6.6。

### 4.4 确定性

> 相同的 (语料内容, `vocab_size`, `min_frequency`, `special_tokens`, `pre_tokenizer_pattern`, 代码版本) ⟹ **完全相同的 merges 序列**。

已实测固化：**2 个独立进程 × `num_shards ∈ {1,4,默认}` 共 6 次训练逐条一致**。所以默认 `num_shards = rayon 线程数` 不影响结果，无需为可复现性固定线程数。

## 5. 输入语料规范

### 5.1 四种 reader

| 构造方式 | CLI `--format` | 语义 | 文本单元 |
|---|---|---|---|
| `TextFileReader(path)` | `text` | 纯文本，**逐行** | 行 |
| `JsonlFileReader.static_text(path)` | `jsonl`（= `jsonl:text`） | 每行 JSON，取 `text` 字段 | 行 |
| `JsonlFileReader.static_conversations(path, sep)` | 仅 Python | 取 `conversations[].content` 并用 `sep` 拼接 | 行 |
| `JsonlFileReader.dynamic(path, schema)` | 仅 Python | 按 schema 从任意 JSON 结构里抽文本 | 行 |

> CLI 的 `train` / `sweep` 的 `--format` 只接受 `jsonl` / `text`，**默认 `jsonl`**；`sample` 按物理行采样、不区分格式。`jsonl:conversations` / `jsonl:dynamic` 目前仅 Python `JsonlFileReader` 支持。

> ⚠️ 默认 `jsonl` 是常见踩坑点：把纯文本 `.txt` 直接喂给 `train` 时，**每一行都会解析失败并被跳过**。2026-11-08 之前这种情形会"成功"产出一个只有 256 个基础字节、0 条 merges 的空模型；现在训练会直接失败并提示改用 `--format text`（Python 侧对应 `TextFileReader`）。

> **行是最小单元**：采样按行、预分词按行。禁止"取前 N 行"做采样（语料按来源排序会引入严重偏置）。

### 5.2 编码、坏行与计数上报

| 情形 | 行为 | 是否可见 |
|---|---|---|
| 非法 UTF-8 字节 | `from_utf8_lossy` 替换为 `U+FFFD`（**行为不变**） | ✅ 计入 `replacement_chars`（**上界值**：原文若已含 U+FFFD 字面量也会被计入） |
| JSONL 坏行 / 缺 `text` 字段 | 静默跳过该行（**行为不变**） | ✅ 计入 `skipped_lines` |
| 空行 | 跳过，不计语料 | 不计 skip |
| 行尾 | 仅剥离 `\r` / `\n`（行尾空格、制表符**保留**） | — |
| 超长 chunk | `> 512` 字节的预分词 chunk 被强切（UTF-8 边界安全） | 写入 `meta.train.max_chunk_bytes` |
| 读取中途 IO 错误（NFS / 坏块 / 句柄错误） | **训练显式失败**（四种 reader 同口径，含 `jsonl:dynamic`）；非严格迭代仅告警 + 终止 | ✅ 计入 `io_errors`（>0 表示语料被截断而非读完） |

训练结束会打印并写入模型 `meta.corpus`：

```
训练语料: 400 行 | 144.67 KB | skipped_lines 0 | replacement_chars 0
⚠️  1523 行被静默跳过（JSONL 坏行 / 缺字段），占比 0.0123%
```

`skipped_lines` 的逐 reader 语义（"行"指物理行）：

| Reader | 计 +1 的条件 |
|---|---|
| `text` | **永不**（任何非空行都是文本） |
| `jsonl:text` | 行非空 且（JSON 解析失败 **或** `text` 缺失） |
| `jsonl:conversations` | 行非空 且（解析失败 **或** `conversations` 缺失 **或** 拼接结果为空） |
| `jsonl:dynamic` | 行非空 且 该行未产出任何文本块（部分字段失败但其他成功 ⟹ 不计） |

### 5.3 训练侧 vs 推理侧的预分词差异（既定语义）

- **训练**：以**行**为单位预分词（行已剥离换行）⟹ 统计中永不见换行符
- **推理**：`encode` 对**整段文本**（含 `\n`）预分词

内置 pattern 都含 `\s+` / `\s*[\r\n]+` 类分支 ⟹ 推理可能产出训练统计中从未出现的跨行空白 token（如 `" \n "`）。这是行级训练的固有属性，**fertility 评估也在同一口径下**进行，不影响可比性。

## 6. 命令行

> 统一入口 `bbpe <子命令>`。不传子命令时打印总览并以退出码 2 结束。各子命令**未提供 `--help`**，
> 但 `bbpe --help` 有总览；缺参数/未知参数时会直接报出原因（如 `--vocab 需要参数`、`未知参数: -x`）。

### 6.1 `train` —— 训练词表（唯一入口）

```bash
# 小语料：全量精确训练
bbpe train --input data/full.jsonl --format jsonl \
    --vocab 100256 --output output/vocab_100k.json

# 大语料：加采样参数即可（其余完全一样）
bbpe train --input data/pretrain.jsonl --format jsonl \
    --vocab 150256 --output output/vocab_150k.json \
    --sample-rate 0.20 --sample-seed 42 \
    --heldout-rate 0.005 --heldout-seed 7 --heldout-out data/heldout.jsonl
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--input` | 必填 | 语料路径 |
| `--output` | `output/vocab.json` | 模型输出路径（自动建目录） |
| `--format` | `jsonl` | `jsonl` \| `text` |
| `--vocab` | `100256` | **总词表大小** = 256 + merges 数 |
| `--min-frequency` | `2` | 终止阈值（不影响选序，见 §4.2 推论） |
| `--sample-rate` | — | 采样率 `[0,1]`。**不传 = 全量训练** |
| `--sample-seed` | `42` | 采样种子（固定 ⟹ 可复现） |
| `--sampling-rate` / `--sampling-seed` | 旧名 | 兼容别名，分别等同 `--sample-rate` / `--sample-seed`；会打印提示 |
| `--heldout-rate` | `0.0` | held-out 采样率（`> 0` 时**必须**配 `--heldout-out`） |
| `--heldout-seed` | `43` | held-out 种子 |
| `--heldout-out` | — | held-out 输出路径（供 `sweep` 用） |
| `--sample-out` | — | 保留采样语料；默认写临时文件并在训练后删除 |
| `--max-bytes` | 无上限 | 读取字节上限（在行边界截断，不产生半行） |

**出身信息是事实，不是转录**：采样与训练在同一进程内完成，`meta.sampling` 由程序据实写入。
未采样时该字段缺省 ⟹ 拿到一个模型，"是否采样训练"一眼可辨（可追溯）。

> ⚠️ **旧命令的行为变更**（有意的修复）：`train_vocab --sampling-rate 0.2` 过去**只写 meta、不采样**
> （用户得自己先跑 `sample_corpus`，且抄错数字模型也不知情）。现在同名参数会**真的采样**。
> 旧脚本若依赖"传了 rate 但喂全量语料"，请去掉该参数。

> **special tokens**：当前 `bbpe train` 未暴露 `--special-token`；需要 special tokens 时用 Python `TrainerConfig.with_special_tokens(...)`（或进阶 bin `bbpe_jsonl_bench --special-token`）。special 的 id 分配见 §4.1，空串会被 V6 拒绝。

**输出解读**：

```
== bbpe train（统一训练入口） ==
  语料: data/pretrain.jsonl [jsonl] | 8.28 GB | 采样率 20.00%
  目标总词表 150256（= 256 基础 + 150000 merges）| min_frequency 2
  采样: 总 12345678 行 ⟹ 训练 2469135 行（1.66 GB，实际率 20.00%，seed=42）
  held-out: data/heldout.jsonl | 61728 行（41.72 MB，与训练集互斥，seed=43）
  训练语料: 2469135 行 | 1.66 GB | skipped_lines 0 | replacement_chars 0

  耗时 412.3s | 峰值内存 6.42 GB
  词表 150256 项（= 256 基础 + 150000 merges）

== 推论 7 判据（vocab_size 是否先到） ==
  ✅ 成立：实际 merges 150000 ≥ 目标 150000 ⟹ vocab_size 是终止原因
     ⟹ 推论 7 生效：m=2 与 m=100 输出 bit-identical，严格/近似模式合一。
```

- **✅ 成立**：语料规模足够支撑该 `vocab_size`，`min_frequency` 的取值不影响输出
- **⚠️ 失效**：实际 < 目标 ⟹ `min_frequency` 才是终止原因，此时 m 的选择会影响输出，应下调 K 或增大样本

**内存预检**：按 `9.2 × 训练语料字节数` 估算峰值 RSS，超可用内存时直接报错并给出建议命令：

```
❌ 语料装不进内存：训练语料 8.28 GB × 9.2 ≈ 76.2 GB，可用内存约 15.6 GB。
   建议加降采样（其余参数不变）：
     bbpe train --input data/pretrain.jsonl --vocab 150256 \
         --sample-rate 0.153 --sample-seed 42 --heldout-rate 0.005 \
         --heldout-out heldout.jsonl
```

### 6.2 `sweep` —— 扫词表规模

**一次训练，评估全部候选规模**（贪心前缀性质，零额外训练成本），并可直接导出。

```bash
bbpe sweep --model output/vocab_150k.json --held-out data/heldout.jsonl --format jsonl \
    --vocabs 8448,16640,33024,49408,65792,98560,131328,150256 \
    --max-bytes 52428800 --export-at 100256
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--model` | 必填 | `K_max` 模型（训练一次即可） |
| `--held-out` | 必填 | held-out 集（与训练集互斥） |
| `--format` | `jsonl` | held-out 的格式 |
| `--vocabs` | 8 档（见下） | **总词表**，逗号分隔 |
| `--max-bytes` | 50 MB | 评估用的 held-out 字节上限 |
| `--export-at` | — | 评估完**直接导出**这些总词表规模的模型 |
| `--export-dir` | 模型同目录 | 导出目录 |
| `--allow-legacy-pattern` | 关 | 加载 v0 旧模型时开启 |

默认 `--vocabs` = `8448,16640,33024,49408,65792,98560,131328,150256`。

> **单位**：与 `--vocab` 完全一致，都是**总词表** = 256 + K。
> 表格里 `总词表` 与 `K` **两列都打印**，不需要心算；
> 若你填了整千值（如 `100000`），工具会提示"看起来像 merges 数，是否想写 100256"。

**输出解读**：

```
       总词表          K  bytes/tok    汉字/tok~    相对最小提升   边际(每+1K)     备注
        65792      65536     5.6921       1.90        0.00%        0.089%
       100256     100000     5.9492       1.98        4.52%        0.071%
```

- `bytes/token` **越高越好**（每个 token 压进更多字节 ⟹ 同样文本需要更少 token）
- 看 `边际(每+1K)` 找**拐点**：边际收益明显衰减处的规模就是性价比最优点

不加 `--export-at` 时，末尾会打印每个候选的 `bbpe cut` 命令，**数字都已换算好，可直接复制**。
加上 `--export-at` 则直接产出模型文件，省掉"看表 → 手算 → 敲命令"这一步。

### 6.3 `cut` —— 从大模型导出任意规模

```bash
bbpe cut --model output/vocab_150k.json --vocab 100256 --output output/vocab_100k.json
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--model` | 必填 | 源模型（K_max） |
| `--vocab` | 必填 | **目标总词表** = 256 + K |
| `--output` | 必填 | 输出路径 |
| `--allow-legacy-pattern` | 关 | 加载 v0 旧模型时开启 |

- 超出源模型 K_max 时自动钳制到 K_max 并告警
- **继承源模型的 `meta`**（出身信息不丢），并把 `train.actual_merges` 修正为截断后的值
- 首次截断写入 `train.truncated_from = 源 vocab_size`；连续多次截断保留最初源规模（`inspect` 会显示"截断自 ..."）

### 6.4 `sample` —— 单独采样（进阶）

```bash
bbpe sample --input data/pretrain.jsonl \
    --train-out data/sample_20p.jsonl --rate 0.20 --seed 42 \
    --heldout-out data/heldout.jsonl --heldout-rate 0.005 --heldout-seed 7 \
    --max-bytes 8589934592
```

日常训练**不需要它**——`bbpe train --sample-rate` 已内建采样。只有当你需要
"同一份样本训多个模型"或做"rate₁ ⊆ rate₂ 嵌套对照"时才用本命令。

参数：`--input` / `--train-out`（必填）、`--rate`(0.2)、`--seed`(42)、`--heldout-out`、
`--heldout-rate`(0.0)、`--heldout-seed`(43)、`--max-bytes`(无上限)。

> 与 `train` 相同：`--heldout-rate > 0` 时必须提供 `--heldout-out`；`--rate` / `--heldout-rate` 必须在 `[0,1]`。

**三条保证**（均有回归测试）：

1. **训练 / held-out 互斥**：held-out 命中的行绝不进训练集
2. **嵌套性**：同 seed 下 `rate₁ < rate₂ ⟹ train₁ ⊆ train₂` ⟹ 可先采大样本再派生小样本做采样率标定
3. **held-out 与 rate 无关** ⟹ 换采样率时 held-out 集不变，评估可跨率比较

吞吐约 **56 MB/s**（8.28 GB 语料 ≈ 2.5 分钟）。

### 6.5 `compare` —— 比较两条 merges 序列

回答"采样率 / 语料规模是否足够"。

```bash
bbpe compare --a output/vocab_150k.json --b output/vocab_150k_5p.json \
    --at 1000,10000,50000,100000,150000
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--a` / `--b` | 必填 | 两个模型 |
| `--at` | `1000,10000,50000,100000,150000` | 在哪些 N 上比较前 N 项 |
| `--allow-legacy-pattern` | 关 | 加载 v0 旧模型时开启 |

> ⚠️ **方法学**：跨模型比较 merges 必须在**字节空间**进行。本项目 `new_id = 256 + i` 由合并次序定义，
> 一旦两条序列在第 i 位分叉，其后所有 id 含义整体错位 ⟹ id 空间重合率会崩到 ~6%，
> 那是**编号错位的假象**。工具会给出 id 空间列，但**仅作对照，不作结论依据**。

三个指标：**逐位一致率**（最严格，第一个分叉点 = 真正偏离点）、**集合重合率**（次序无关）、**id 空间重合率**（对照）。

判据：分叉点越靠后越好；**若分叉点在实际使用的 K 之后，则两模型对下游等价**。

### 6.6 `inspect` —— 模型体检与迁移

```bash
# ① 摘要 + 自洽性校验
bbpe inspect output/vocab_100k.json

# ② 只校验（CI 用，退出码 0 = 通过 / 1 = 失败）
bbpe inspect output/vocab_100k.json --validate-only

# ③ 迁移 v0 → v1（pattern 必须显式给）
bbpe inspect --migrate old_model.json new_model.json --pattern "$(cat pattern.txt)"
```

| 参数 | 说明 |
|---|---|
| `<model>` | 位置参数，模型路径 |
| `--validate-only` | 只校验，退出码 0/1 |
| `--allow-legacy-pattern` | 查看 v0 模型时允许回退 DEFAULT_PATTERN |
| `--migrate <in> <out>` | 迁移模式 |
| `--pattern <regex>` | 迁移时写入的 pattern（**必须显式提供，工具不猜**） |

输出示例：

```
== bbpe inspect（模型契约 v1） ==
  文件: output/vocab_100k.json
  format: bbpe-rs-model | format_version: 1（本程序支持 1）
  词表 100256 项 | merges 100000 | special tokens 0
  pre_tokenizer_pattern: (?x) …（共 371 字符）
  meta:
      created_at:      2026-09-08T01:50:07Z
      bbpe_rs_version: 0.1.0
      git_commit:      6b5b33d
      profile:         v2
      corpus:          reader=jsonl:text lines=2469135 bytes=1660000000 skipped=0 replacement=0
      sampling:        rate=0.2 seed=42 heldout_rate=0.005 heldout_seed=43（采样训练）
      train:           vocab_size=150256 min_frequency=2 actual_merges=100000 end_reason=vocab_size_reached max_chunk_bytes=512
  ✅ V1–V6 自洽性校验通过
```

> `sampling` 行显示"（采样训练）"；全量训练的模型该字段为"未记录（全量训练，未采样）"。
> `inspect` 还会显示 `profile`（当前统一 CLI/Python 写 `v2`）与 `eval`（若模型带评估元信息）；`cut` 产物的 `train` 行会追加 `[截断自 vocab_size=...]`。
> `inspect --migrate` 只补写 `format` / `format_version` / `pre_tokenizer_pattern`，vocab/merges/meta 原样保留；完成后重新执行 V1–V6。
> `--allow-legacy-pattern` 只豁免 `pre_tokenizer_pattern` 缺失（回退 DEFAULT_PATTERN），**不豁免 V1–V6**；校验失败仍报 `ModelValidation`。

**V1–V6 校验规则**：

| # | 规则 |
|---|---|
| V1 | vocab 含 0–255 全部基础字节 |
| V2 | 每条 merge 的 `(p0,p1)` 与 `new_id` 都在 vocab 中（词表闭合） |
| V3 | `new_id` 集合恰为连续区间 `{256 … 256+m−1}`（保证"按 id 截断 = 前 k 次合并"） |
| V4 | `pre_tokenizer_pattern` 可编译 |
| V5 | special token id 互不重复、均在 merge id 之后（尾部性质），且字节与 vocab 一致 |
| V6 | special token 文本非空（空串会使 encode panic，2026-10-12 增补） |

### 6.7 `encode` —— 用模型编码文本

```bash
# 直接编一段文本
bbpe encode --model output/vocab.json --text '你好，世界'

# 从文件读（编码整段内容，含换行）
bbpe encode --model output/vocab.json --file data/dev.txt

# 机器可读（ids / tokens / offsets 全量，供回归与管道消费）
bbpe encode --model output/vocab.json --file data/dev.txt --json
```

| 参数 | 说明 |
|---|---|
| `--model <path>` | 模型路径（必填） |
| `--text <s>` / `--file <path>` | 待编码文本，二选一（必填） |
| `--allowed-special a,b` | special token 白名单：命中的整体成词；任一项为 `all` 即放行全部（tiktoken 式约定） |
| `--all-special` | 放行全部 special token（等价于白名单 `all`） |
| `--json` | 输出 `{"ids": [...], "tokens": [...], "offsets": [[s,e],...]}` |
| `--allow-legacy-pattern` | v0 模型（缺 pattern）允许回退 DEFAULT_PATTERN |

默认（无白名单）一个 special 都不放行——未授权 special 会被切碎成字节，
与 `encode_ordinary` 同语义，是防注入侧的正确默认。注意 `encode` 只接受合法
UTF-8 文本；非法字节序列需调用方自行预处理（`from_utf8_lossy` 会引入 U+FFFD，
改变 token 序列）。

### 6.8 `decode` —— 用模型解码 id 序列


| 参数 | 说明 |
|---|---|
| `--model <path>` | 必填，模型路径 |

| `--json` | 输出 `{"text": "...", "n_tokens": N}` |

## 7. 典型工作流

### 7.1 A：小语料（能装进内存）

**不要采样**——全量训练是唯一保证严格等价的路径。

```bash
bbpe train --input data/full.jsonl --format jsonl \
    --vocab 100256 --output output/vocab_100k.json
bbpe inspect output/vocab_100k.json --validate-only
```

### 7.2 B：大语料（远超内存）

```bash
# ① 训练：内建采样（20%）+ held-out（0.5%，互斥）
bbpe train --input data/pretrain.jsonl --format jsonl \
    --vocab 150256 --output output/vocab_150k.json \
    --sample-rate 0.20 --sample-seed 42 \
    --heldout-rate 0.005 --heldout-seed 7 --heldout-out data/heldout.jsonl

# ② 扫规模并直接导出选定档（单位与 ① 的 --vocab 一致）
bbpe sweep --model output/vocab_150k.json --held-out data/heldout.jsonl \
    --vocabs 33024,49408,65792,98560,131328,150256 --export-at 100256

# ③ （可选）验证采样充分性：再训一个 5% 模型比对分叉点
bbpe train --input data/pretrain.jsonl --vocab 150256 \
    --output output/vocab_150k_5p.json --sample-rate 0.05 --sample-seed 42
bbpe compare --a output/vocab_150k.json --b output/vocab_150k_5p.json \
    --at 1000,10000,50000,100000
```

> **为什么选 K 与训练解耦**：贪心前缀性质（§4.2）让 `sweep` + `cut` 用**一次训练**完成选 K 与导出，切 K 不需要重训。

### 7.3 C：既有模型的检查与迁移

```bash
# ① 全量盘点
for f in output/*.json; do
  bbpe inspect "$f" --validate-only || echo "❌ $f"
done

# ② v0 旧模型（报 MissingPreTokenizerPattern）迁移
bbpe inspect --migrate output/old.json output/new.json --pattern "$(cat my_pattern.txt)"

# ③ 临时方案（不推荐，会回退 DEFAULT_PATTERN 并告警）
bbpe cut --model old.json --vocab 100256 --output new.json --allow-legacy-pattern
```

⚠️ **`--allow-legacy-pattern` 只是权宜之计**：若该模型当初用非默认 pattern 训练，回退 DEFAULT_PATTERN 会得到**错误且无声**的分词结果。

## 8. Python API

### 8.1 底层 `bbpe_rs`

```python
from bbpe_tokenizer import bbpe_rs

# ---------- 训练 ----------
cfg = (bbpe_rs.TrainerConfig(100256)
        .with_pattern(bbpe_rs.PatternFlavor.gpt4())      # 或 .llama3() / .custom(r"(?x) ...")
        .with_min_frequency(2)
        .with_special_tokens(["<|im_start|>", "<|im_end|>"]))

rt = (bbpe_rs.RuntimeConfig()
        .with_batch_size(50_000)
        .with_num_shards(8)
        .with_parallel_index(True))

reader = bbpe_rs.JsonlFileReader.static_text("data/train.jsonl")
# 其他 reader：
#   bbpe_rs.TextFileReader("corpus.txt")
#   bbpe_rs.JsonlFileReader.static_conversations("chat.jsonl", separator="\n")
#   bbpe_rs.JsonlFileReader.dynamic("data.jsonl", {"a": ("/text", "str")})

trainer = bbpe_rs.BBPETrainer(cfg, rt)
trainer.train(reader)   # 采集 skipped_lines / replacement_chars 并写入 meta.corpus
trainer.save("output/vocab.json")
```

> `JsonlFileReader.dynamic` 按 **dict 插入顺序** 逐条尝试 schema 规则，命中即提取；多字段时顺序即优先级。

> `TrainerConfig(vocab_size)` 默认 `min_frequency=2`、`pattern=PATTERN_CHINESE_OPTIMIZED`、`special_tokens=[]`；`RuntimeConfig` 默认 `batch_size=50000`、`num_shards=rayon 线程数`、`parallel_index_build=True`（Python 方法 `with_parallel_index`）、`max_chunk_bytes=512`。`BBPETrainer(cfg, rt)` 的 `rt` 可省略（等价于 `RuntimeConfig()`）。

> `with_num_shards` 默认 = rayon 线程数，**不影响训练结果**（确定性已实测固化，§4.4）。
> Python 侧训练**默认**等价 CLI 的全量训练；需要采样时直接给 `train()` 传 `sample_rate=` / `sample_seed=` / `max_bytes=`（见下方「Python 侧采样与内存预检」），出身信息由程序据实写入。

**训练与 Python 并发**

`trainer.train()` 已**释放 GIL**：训练在 worker 线程执行，主线程每 20ms 做一次信号泵，因此同进程内其它 Python 线程可正常推进，Ctrl+C 也能中断训练并返回原始的 `KeyboardInterrupt`。旧注释把障碍归因于「`CorpusReader` 内含 `BufReader<File>`、不满足 `Send`」并不准确：reader 是纯 `String`/`Vec` 的 enum，真正边界是 `PyRef<'py, T>` 借用加上 `py.detach` 的 `Ungil`（stable 上等价 `Send`）约束，现已通过在持 GIL 时 clone 出 owned reader、把训练态 `take()` 进 worker 解决。

**取消语义**：取消即**丢弃训练态**，`save()` 会拒绝；请先 `trainer.reset()` 或新建 trainer 重训。异常附带 `merges_done` / `reason` / `elapsed_secs` / `corpus_stats` 属性。几十 GB 训练态在后台线程释放，`wait_cleanup()` 可显式等待；下一次 `train()` / `reset()` 会自动回压，避免双份峰值 OOM。

三种取消源：

```python
# ① 主线程调用：Ctrl+C 直接生效，无需额外代码
trainer.train(reader)

# ② 程序化取消 / 超时（任意线程可用；抛 TrainingCancelled）
tok = CancellationToken()
trainer.train(reader, cancel_token=tok, timeout=3600)
tok.cancel()

# ③ 训练跑在后台线程：把主线程的 Ctrl+C 桥接过来
with bbpe_tokenizer.interruptible() as tok:
    t = threading.Thread(target=lambda: trainer.train(reader, cancel_token=tok))
    t.start()
    t.join()
```

非主线程直接调用 `train()` 时 Ctrl+C **不会自动生效**（`PyErr_CheckSignals` 只在主线程调用 Python 信号处理器），入口会发一条 `warnings.warn` 提示改用 `cancel_token` / `timeout` / `interruptible()`；`interruptible()` 在非主线程调用时也不再报错，退化为「只返回令牌 + 一条 `RuntimeWarning`」。自定义 `signal.signal` handler 抛出的异常会**原样**传回，不会被替换成 `RuntimeError`。

> **CPython 3.12 的已知差异**：用 `interruptible()` 包住**后台线程**训练时，主线程会正常收到 `KeyboardInterrupt`、训练也确实被取消（`save()` 拒绝、无半截模型），但 worker 线程可能在取消瞬间被提前终止，来不及把 `TrainingCancelled` 交回 Python 层（实测连 `finally` 都不执行）；3.13 上不会出现。若清理逻辑依赖 worker 侧的 `except TrainingCancelled`，请改用 `cancel_token` + 主线程轮询 `tok.cancelled`，或在主线程直接训练。

**推理侧中断**：`encode` / `encode_ordinary` / `encode_parallel` / `encode_ordinary_parallel` / `decode` 对超长输入（文本 ≥ 1 MiB、decode 的 ids ≥ 200000）自动启用同样的 worker + 信号泵；短输入仍走零开销原路径。取消语义是**放弃本次结果**：encode/decode 是纯函数、不改共享状态、无 I/O，主线程可立即返回原始 `KeyboardInterrupt`，worker 计算到本次调用结束即可，结果被丢弃。

**CLI 优雅取消**：`bbpe train` 注册进程级 SIGINT handler，把 Ctrl+C 转成取消令牌；训练在检查点返回 `Err(Cancelled)`，CLI 正常展开调用栈 —— 进度条 abandon、临时采样文件由 `TempFileGuard` 清理、原始语料不做任何改动，并以明确的取消信息非零退出。此前 SIGINT 直接终止进程，Drop 不会运行，会遗留 GB 级临时文件。

**大训练态释放实测**（可复现：`BBPE_DROP_PROBE_GB=85 cargo run --release --example cancel_drop_probe`）：85 GB 同构训练态在 worker 线程异步释放，主线程返回延迟 **0.207 ms**，worker 释放 **4.918 s**，RSS 从 87 GB 回落到 2.1 MB。真实训练态交叉验证（106 MB 语料 / 峰值 0.33 GB）：`wait_cleanup()` 耗时 **0.207 s**。基准用分散 `Vec` 块模拟大量小分配，真实 `AHashMap` / `Shard` 结构更复杂，数字应视为量级估计而非上界。

**Python 侧采样与 OOM 内存预检**

`train()` 支持 `sample_rate` / `sample_seed` / `max_bytes` / `oom_precheck` / `heldout_rate` / `heldout_seed` / `heldout_out` / `sample_out`：

- 采样复用 CLI 的 `sampling::sample_lines` 语义（行级均匀随机、固定种子、同 seed 下 `rate₁ < rate₂ ⇒ train₁ ⊆ train₂` 的嵌套性），**保持原 reader 变体**（jsonl 仍是 jsonl，不会退化成纯文本解析）。采样出身信息据实写入 `meta.sampling`（`rate` / `seed` / `heldout_rate` / `heldout_seed`），全量训练时该块缺省。
- **采样预读 → OOM 预检 → 训练整体在 worker 线程执行**，主线程信号泵从一开始就覆盖全流程：`sample_lines_cancel` 每 4096 行检查取消令牌，因此 200GB 语料的预读阶段也能被 Ctrl+C / `cancel_token` / `timeout` 停止，不必等预读跑完。
- 临时样本文件由 `TempFileGuard` 在 worker 结束时清理（成功 / 失败 / 取消一视同仁），取消路径另有主线程兜底删除，防止进程抢先退出导致残留。传 `sample_out=` 可保留采样语料；`heldout_rate > 0` 时必须提供 `heldout_out=`（否则命中行会被静默丢弃）。所有输出路径都会做别名防护，不能覆盖原始语料。
- **`sample_out` / `heldout_out` 采用原子落盘**：先写同目录 `.{名字}.part.{pid}.{nanos}` 暂存文件，采样完整成功后才 `rename` 到目标路径。因此取消、采样 IO 错误、OOM 预检失败都**不会改动目标文件一个字节**，已有同名文件不会被截断成半截产物；`heldout_rate = 0` 时即使传了 `heldout_out` 也不会创建空文件。
- `oom_precheck` **默认开启**：按 `9.2 × 训练语料字节数` 与有效可用内存比较，在开工前拦截必然 OOM 的配置并给出建议 `sample_rate`。可用内存取 `/proc/meminfo` 的 `MemAvailable`（缺失回退 `MemTotal`）与 cgroup 限额（v2 `memory.max` / v1 `memory.limit_in_bytes`）的较小值，容器场景不会误判；三者都读不到时**显式发一条 `RuntimeWarning`** 告知预检被跳过，而不是静默放行。失败分支**绝不改动任何用户输入文件**（既定约束）；可用 `oom_precheck=False` 显式关闭。
- 与 `bbpe train --sample-rate` 同 seed 的训练结果逐位一致（已有回归测试）。

```python
trainer.train(reader, sample_rate=0.02, sample_seed=42)  # 大语料按 2% 采样
trainer.train(                                           # 采样 + held-out 并保留两份产物
    reader, sample_rate=0.05, sample_out="train.jsonl",
    heldout_rate=0.005, heldout_out="heldout.jsonl",
)
trainer.train(reader, oom_precheck=False)                 # 自行承担 OOM 风险
```

> 同一 trainer 只能训练**一次**：二次 `train()` 会抛
> `RuntimeError: ... 已训练过 ... 调用 reset()`（`merges`/`vocab` 会残留，`new_id`
> 从 256 重启后与残留 id 撞车 ⟹ 产出的模型连 `inspect --validate-only` 都过不了）。
> 换语料重训请先 `trainer.reset()`，或新建 trainer；`trainer.is_trained()` 可自查。

```python
# ---------- 分词 ----------
tok = bbpe_rs.BBPETokenizer("output/vocab.json")
# 加载 v0 旧模型（缺 pre_tokenizer_pattern，回退 DEFAULT_PATTERN 并打印警告）：
tok = bbpe_rs.BBPETokenizer("old_model.json", allow_legacy=True)

ids = tok.encode_ordinary("人工智能")                    # 拒绝一切 special，最快
enc = tok.encode("你好 <|im_end|>", allowed_special=["<|im_end|>"])   # ids/tokens/offsets
enc = tok.encode(text, allowed_special=["all"])          # 允许全部 special

# 长文本（> 5000 字节走 rayon 并行，结果与串行一致）
ids = tok.encode_ordinary_parallel(long_text, num_threads=8)
enc = tok.encode_parallel(long_text, allowed_special=["all"], num_threads=8)

text = tok.decode(ids)                                   # round-trip 无损

provides, hangs = tok.get_utf8_token_props(token_id)     # FSM 属性
cont = tok.get_valid_continuations(pending_bytes=1)       # 合法续接 token
tok.save("output/copy.json")

bbpe_rs.init_rust_logger()                               # 打开 Rust 侧日志
```

`encode` 返回 `Encoding(ids, tokens, offsets)`，`offsets` 是字节区间 `[start, end)`。

> **推理 API 的错误语义**：Python 绑定的四个编码入口（`encode` / `encode_ordinary` /
> `encode_parallel` / `encode_ordinary_parallel`）与 `decode`（合称五个推理入口）均为**严格路径**：预分词失败
> （自定义 pattern 未覆盖全部文本）抛 `RuntimeError`，不会返回空/不完整结果。
> Rust 侧另有非严格快速路径（`BBPETokenizer::encode_ordinary` 等，签名不返回 `Result`），
> 失败时大声报警后返回不完整结果 —— 仅限显式选用它的 Rust 调用方；需要硬失败请用
> `encode_checked` / `encode_ordinary_checked` / `encode_parallel_checked` / `encode_ordinary_parallel_checked`。

> **模型加载的 id 跨度预算（既定取舍）**：加载器按 `max_id + 1` 预分配两份
> 稠密数组（≈ 40 B/条），故 id 跨度超过 **16,777,216**（`MAX_MODEL_ID_SPAN = 1<<24`，约 670 MB
> 上限）的模型会在加载期被拒绝（`validate=false` 亦生效），以防御稀疏大 id 的损坏/恶意模型
> 触发 GB 级分配。该值为编译期常量、不可配置；对 256 + merges + specials 的常规模型无影响
> （十万级词表的 id 跨度远小于预算）。若确需预留超大词表（id 跨度 > 16.7M），需修改源码
> 常量并重新构建，同时自行承担相应的内存开销。

> `get_utf8_token_props(id)` 返回 `(provides, hangs)`：`provides` 是该 token 补全的字节数，`hangs` 是仍挂起的字节数；`hangs == 0` 才可安全截断。`get_valid_continuations(pending_bytes)` 支持 0–3，返回当前状态下所有合法续接 token id。

⚠️ `encode_parallel` / `encode_ordinary_parallel` 内部用 rayon 线程池，**不要在依赖 `os.fork()` 的多进程环境（PyTorch DataLoader、Celery）里盲目调用**。

### 8.2 高层 `BBTokenizer`

```python
from bbpe_tokenizer import BBTokenizer

tok = BBTokenizer.from_pretrained("output/model_dir")     # 读 tokenizer.json + tokenizer_config.json

tok.encode("你好")                                        # ids/tokens/offsets
tok.encode_ordinary("你好")
tok.encode_parallel("长文本", allowed_special=["all"], num_threads=8)
tok.encode_ordinary_parallel("长文本", num_threads=8)
tok.decode(ids)

# Jinja2 chat template（需 tokenizer_config.json 里配 chat_template）
ids = tok.apply_chat_template(
    [{"role": "user", "content": "你好"}, {"role": "assistant", "content": "您好"}],
    add_generation_prompt=True, tokenize=True)

# SFT：自动构造 labels（-100 掩码），content 用 encode_ordinary 防注入
out = tok.encode_dialogue_safely([
    {"role": "user", "content": "你好"},
    {"role": "assistant", "content": "您好"},
])
input_ids, labels = out["input_ids"], out["labels"]

tok.save_pretrained("output/model_dir")
```

> `encode_parallel` / `encode_ordinary_parallel` 在文本 <5000 字节时自动回退串行；结果与串行一致。

**生成时防乱码（流式输出 / 推理部署）**：

```python
from bbpe_tokenizer import UTF8StrictLogitsProcessor

processor = UTF8StrictLogitsProcessor(tok, batch_size=1, device="cuda")
# 传给 transformers.generate(logits_processor=[processor])
```

它用 Rust 预计算的 FSM（`get_valid_continuations` / `get_utf8_token_props`）在 GPU 侧掩盖非法 UTF-8 续接 token，大幅降低流式输出中的汉字断裂/乱码。Rust 侧 FSM 已把 C0/C1（overlong）与 F5–F7（超出 U+10FFFF）排除出合法前导字节；注意它保证的是**前导字节级**约束（“悬空前导字节必须被补齐、非法前导不开启悬空”），并非完整的 UTF-8 校验器（surrogate / 超范围标量取决于词表内容，以 decode 为准），且依赖掩码不被其它 LogitsProcessor 绕过。类名 `UTF8StrictLogitsProcessor` 中的 “Strict” 为历史名称，为兼容 API 保留。

### 8.3 高层配置 `TokenizerGlobalConfig`

`BBTokenizer.from_pretrained` 读 `tokenizer.json` + `tokenizer_config.json`；`save_pretrained` 写回两份文件。常用字段：

| 字段 | 默认 | 作用 |
|---|---|---|
| `bos_token` / `eos_token` | `<\|im_start\|>` / `<\|im_end\|>` | 对话边界 |
| `pad_token` / `unk_token` | `<\|endoftext\|>` | 填充 / 未知 |
| `role_system` / `role_user` / `role_assistant` | `system` / `user` / `assistant` | chat 角色名 |
| `tool_call_start` / `tool_call_end` | `<tool_call>` / `</tool_call>` | 工具调用包裹 |
| `think_start` / `think_end` | `<think>` / `</think>` | 推理段包裹 |

| `chat_template` | 内置模板 | Jinja2 字符串；可被 `tokenizer_config.json` 覆盖 |

`TokenizerGlobalConfig.to_dict()` 生成 `tokenizer_config.json` 的字典；`save_pretrained` 内部使用它。

## 9. 模型文件格式（契约 v1）

```jsonc
{
  "format": "bbpe-rs-model",           // MUST，固定值
  "format_version": 1,                 // MUST
  "vocab": { "4": [4], "267": [142,159] },   // MUST，id(字符串) → 字节数组
  "merges": { "152,229": 274 },              // MUST，"p0,p1" → new_id
  "pre_tokenizer_pattern": "(?x)...",        // MUST（缺失 ⟹ 加载报错）
  "added_tokens": { "<|im_end|>": 100000 },  // MAY
  "meta": {                                  // MAY，纯记录；未知字段被忽略
    "created_at": "2026-09-08T01:50:07Z",
    "bbpe_rs_version": "0.1.0",
    "git_commit": "6b5b33d",
    "profile": "v2",                        // MAY，元信息；当前统一入口写 v2
    "corpus":  { "reader": "jsonl:text", "total_lines": …, "total_bytes": …,
                 "skipped_lines": …, "replacement_chars": … },
    "sampling": { "rate": 0.2, "seed": 42, "heldout_rate": 0.005, "heldout_seed": 43 },
    "train":   { "vocab_size": 150256, "min_frequency": 2, "actual_merges": 100000,
                 "end_reason": "vocab_size_reached", "max_chunk_bytes": 512,
                 "truncated_from": 150256 },
    "eval":    { "held_out_bytes": …, "fertility_at_k": { "65536": 5.6921 } }
  }
}
```

**设计要点**：

- vocab 用 **id → 字节数组**（不是字符串）：byte-level BPE 的 token 可能是非法 UTF-8 片段，字节表示**无损**
- `format_version` 是格式演进的唯一锚点
- `meta` 是纯记录，加载器**忽略未知字段** ⟹ 旧代码能读新模型
- `meta.sampling` **缺省即表示全量训练**（采样训练时由 `train` 据实写入）
- `meta.profile` 仅元信息；当前统一 CLI / Python 写 `v2`，不代表格式差异
- `meta.train.truncated_from` 仅在 `cut` 产物出现，记录源 `vocab_size`；`inspect` 会显示"截断自 ..."
- `meta.eval` 为预留字段；当前 `sweep` 不自动写入，可由外部评估工具补充
- Python / `TrainerConfig` 里的 `special_tokens` 在模型文件中写作 `added_tokens`；两者是同一条数据的两种叫法
- `git_commit` / `bbpe_rs_version` 由构建期注入；`release.sh` 会校验产物与 HEAD 一致
- 当前 CLI / Python 未暴露 `--no-meta` / `--compact`，模型文件始终 pretty + 带易变 meta；需要逐字节 diff 时用 Rust `SaveOptions{no_meta}`
- `end_reason = "min_frequency_terminated"` 时说明语料规模不足以支撑该 `vocab_size`（推论失效）

## 10. 故障排查

| 症状 / 报错 | 原因 | 处置 |
|---|---|---|
| `MissingPreTokenizerPattern` | v0 旧模型（无 pattern 字段） | `bbpe inspect --migrate` 迁移；或临时 `--allow-legacy-pattern` |
| `VocabSizeTooSmall(258)` 之类 | `vocab_size` 装不下 256 基础字节 + 全部 special tokens | 增大 `vocab_size` 或减少 special tokens |
| `--vocab 是总词表大小…必须 > 256` | 把 merges 数 K 当成了总词表 | 写成 256+K（如 K=100000 → 100256）；`sweep`/`cut` 同口径 |
| `InvalidModelFormat: 含 format 但缺 format_version`（或反之） | 文件被手工编辑/损坏；v1 起两者必须同时存在 | 重新导出/训练；或用 `bbpe inspect --migrate` 重建 |
| `ModelValidation: V3 违反 …` | 模型的 `new_id` 不连续（被手工编辑过或来自外部） | 模型已损坏，重新训练或找回原始文件 |
| `ModelValidation: V6 违反 …` | special token 文本为空（空串会在每个位置匹配并 panic） | 删除空 special；重新训练/导出 |
| `UnsupportedFormatVersion(99, 1)` | 用更高版本 bbpe 训的模型 | 升级 bbpe |
| `RegexError` / `PreTokenize` | 自定义 `pattern` 无法编译或预分词失败 | 用 `bbpe inspect` 校验 pattern；修正后重训/迁移 |
| 训练时报"语料装不进内存 … 建议加降采样"（`CapacityExceeded`） | 内存预检未通过（峰值 ≈ 9.2× 语料） | 按提示加 `--sample-rate`，或换更大机器 |
| 推论 7 判据 ⚠️ 失效 | 语料规模撑不起该 `vocab_size` | 下调 K 或增大样本量 |
| `--heldout-rate > 0 时必须同时提供 --heldout-out` | 参数组合非法（否则 held-out 行会被静默丢弃） | 补 `--heldout-out` |
| `--heldout-out 但 --heldout-rate = 0` | 会产生空的 held-out 文件，后续 sweep 无意义 | 补 `--heldout-rate` 或去掉 `--heldout-out` |
| `cut` 报"源模型 merges 不足" | 目标 `--vocab` 超过源模型 K_max | 已自动钳制到 K_max；如需更大 K 需重训 |
| 填了 `100000` 被提示"看起来像 merges 数" | 单位仍是旧口径 | 总词表应写 `100256`（= 256 + 100000） |
| `bench` / `run_real_data` / `bbpe_jsonl_bench` 报 `MissingPreTokenizerPattern` | 这三个通用 bin 无 legacy 开关 | 先用 `bbpe inspect --migrate` 把模型迁到 v1 |
| Python: `ModuleNotFoundError: bbpe_rs` | 扩展没编译 | `maturin develop --release` |
| 并行编码在 DataLoader 里卡死 | rayon 线程池 + fork 冲突 | 用串行 `encode_ordinary`，或在 worker 外预分词 |
